# 变更摘要 · 2026-10-03

## 19:01 · Batch 1：P0-2 打包预设加载修复 + 启动日志补强

- **P0-2**：`preset_loader.js` 的 `loadPresetLayers`/`initPresetsAsync` 新增 `extraSearchPaths`
  宿主注入候选层（优先级低于用户层）；`ffmpeg-environment.ts` 把打包后的
  `<resources>/presets/default.yaml` 传入。修复打包后 `import.meta.url` 定位失效
  （指向 asar 内不存在的 `app.asar/presets/`）导致预设列表为空、应用不可用的问题。
  预设加载成败均写入 startup log（logs/ffconv-gui-startup.log）。
- **日志补强（关键点/catch 记录点）**：
  - 主进程新增面板日志背板：窗口未就绪期间（`initialize()` 先于 `createWindow()`）
    的 INFO/WARN/ERROR 不再被丢弃，渲染层经新 IPC 通道 `app:renderer-ready`
    （`DesktopApi.signalReady()`）订阅完引擎事件后统一重放。
  - `handleTrusted` 统一捕获 handler 异常并以 ERROR 落 GUI 日志面板（如
    `env:get-presets` 预设目录加载失败），原样 rethrow 不改变渲染层错误处理。
  - `whenReady` 链失败：错误写面板背板 + 仍创建窗口（失败子步骤可在 UI 内重试）
    + 原生 `showErrorBox` 提示，不再「进程活着但无窗口无提示」。
  - 渲染层 `env.ts`：`fetchPresets`/`fetchEnv` 失败追加到日志面板（此前仅 console）。
- **P2-4**：新增 `src/main/app-identity.ts`，在 main 进程任何 `getPath("userData")`
  之前设置 `app.name`；修复 queue/whitelist/manifest 落在 `%AppData%/ffconv-gui`、
  settings 落在 `%AppData%/FFConv GUI` 的目录分裂。`initialize()` 增加一次性迁移
  （仅复制目标侧缺失的 queue.json / authorized-paths.json / active-tasks.json，不覆盖）。
- **P2-6**：单实例锁失败分支 `app.quit()` 后追加 `process.exit(0)`，避免第二实例
  继续注册 22 个 IPC handler 与持久化 store。
- 验证：`npm run typecheck` / `npm run lint` / `npm run test:unit`（38 通过）全绿；
  extraSearchPaths 分层加载实机验证（29 预设正常并入，同名层按 `_override` 规则跳过）。
