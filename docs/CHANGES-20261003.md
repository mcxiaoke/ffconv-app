# 变更摘要 · 2026-10-03

## 19:08 · Batch 3：P0-3 事件双重订阅 + P1-11 停止卡死

- **P0-3**：删除 `App.vue` onMounted 末尾的第二次 `window.api.onEngineEvent(...)`
  订阅（:660-661 追加时漏删）。此前每条引擎事件被处理两次（日志面板每行重复、
  转码完成系统通知双弹），且第二次赋值覆盖退订句柄，第一个监听器在组件卸载后
  永久挂在 `ipcRenderer` 上继续写 store。
- **P1-11**：`stopExecution` 检查主进程返回值：`ok:false`（状态漂移、无运行中任务）
  时不再留渲染层状态卡死在 STOPPING，改为按 `getExecutionStatus()` 快照对账回真实
  终态（`reconcileExecutionStatus`），并写 WARN 日志。此前 isBusy() 恒真会让
  扫描/开始/移除/重排全部静默失效，无自愈路径只能重启应用。
  IPC reject（传输层错误）行为不变（ERROR 日志）。
- 验证：typecheck / lint / test:unit（52 通过）全绿。

## 19:06 · Batch 2：引擎修复（P0-1 / P0-4 / P1-2，含单测）

- **P0-1 外挂字幕丢音轨**：`ffmpeg_tags.js` 外挂字幕分支的流映射补上 `-map 0:a?`。
  此前只映射视频（绝对序号）+ 字幕（`1:0?`），ffmpeg 因任意 `-map` 切入手动流选择，
  源的全部音轨被静默丢弃——视频旁放一个同名 `.srt/.ass/.ssa` 即触发（自动挂载）。
  真机对照验证：修复前产物 0 条音频流，修复后双音轨完整保留。
  新增 `tests/unit/subtitle-map.test.js`（5 用例，含音频预设不参与流映射的防回归）。
- **P0-4 音频码率被智能码率覆盖**：`ffmpeg_plan.js` 音频分支判定顺序改为
  「显式声明（userArgs.audioBitrate > 预设 audioBitrate）> smartBitrate」。
  此前 `aac_high/medium/low/he` 继承基类 `smartBitrate:true`，声明的 256k/192k/128k/96k
  全被智能档位顶掉（320K 源一律出 320K），且 suffix 把错误码率写进文件名。
  智能码率仅在未声明任何 audioBitrate 时生效；未声明且 smartBitrate=false 保持旧行为（0）。
  新增 `tests/unit/audio-bitrate.test.js`（7 用例，覆盖优先级/夹取/48k 兜底）。
- **P1-2 音频任务丢失 caps**：`ffmpeg_run.js` 的 `resolveEntryHwPlan` 音频早返回分支
  补上 `caps`（优先用宿主传入，否则内部探测，有进程内缓存）。
  此前 `buildAudioArgs` 拿到 undefined caps，编码器静态降级链
  （如 nonfree-only 的 libfdk_aac → aac）完全失效。
  `tests/unit/entry-hwplan.test.js` 补 2 条 caps 回传断言。
- 验证：`npm run typecheck` / `npm run lint` / `npm run test:unit`（52 通过）全绿；
  P0-1 经真机 ffmpeg/ffprobe 复核。

## 19:01 · Batch 1：P0-2 打包预设加载修复 + 启动日志补强

- **P0-2**：`preset_loader.js` 的 `loadPresetLayers`/`initPresetsAsync` 新增 `extraSearchPaths`
  宿主注入候选层（优先级低于用户层）；`ffmpeg-environment.ts` 把打包后的
  `<resources>/presets/default.yaml` 传入。修复打包后 `import.meta.url` 定位失效
  （指向 asar 内不存在的 `app.asar/presets/`）导致预设列表为空、应用不可用的问题。
  预设加载成败均写入 startup log（logs/ffconv-gui-startup.log）。
- **日志补强（关键点/catch 记录点）**：
  - 主进程新增面板日志背板：窗口未就绪期间（`initialize()` 先于 `createWindow()`）

    （`DesktopApi.signalReady()`）订阅完引擎事件后统一重放。

    `env:get-presets` 预设目录加载失败），原样 rethrow 不改变渲染层错误处理。
  - `whenReady` 链失败：错误写面板背板 + 仍创建窗口（失败子步骤可在 UI 内重试）
    + 原生 `showErrorBox` 提示，不再「进程活着但无窗口无提示」。
  - 渲染层 `env.ts`：`fetchPresets`/`fetchEnv` 失败追加到日志面板（此前仅 console）。
- **P2-4**：新增 `src/main/app-identity.ts`，在 main 进程任何 `getPath("userData")`
  之前设置 `app.name`；修复 queue/whitelist/manifest 落在 `%AppData%/ffconv-gui`、
  settings 落在 `%AppData%/FFConv GUI` 的目录分裂。`initialize()` 增加一次性迁移
  （仅复制目标侧缺失的 queue.json / authorized-paths.json / active-tasks.json，不覆盖）。
- **P2-6**：单实例锁失败分支 `app.quit()` 后追加 `process.exit(0)`，避免第二实例
