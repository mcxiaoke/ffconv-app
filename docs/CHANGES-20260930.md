# 变更记录

## 2026-09-30

### 修复（第一批：转码引擎 core/transcode、core/lib）

- **修复封面图被当作主视频流，导致转码产出 1 帧静态图却报"成功"**（P0）
  - 根因：ffmpeg 参数里硬编码 `-map 0:v:0`（"第 0 个 video 流"），而内嵌封面也被探测为 video 流。
    带封面的 MKV 实测封面即 stream0、真实视频为 stream1，于是选中封面；
    ffmpeg 退出码为 0，且产物大小校验也拦不住，UI 显示成功。
    另实测：只给 `-map 0:a?` 而不给视频流时，ffmpeg 会自动补回 stream0（封面）。
  - 修复：媒体信息新增**绝对流序号** `video.streamIndex`（ffprobe `index` / mediainfo `StreamOrder`），
    流映射改用 `-map 0:<绝对序号>`；两种探测器的封面识别统一为"三档"判定
    （确证封面 attached_pic/@type=Image、疑似封面=静帧编码器、正常视频），
    取不到序号时整组 `-map` 都不输出，交由 ffmpeg 默认流选择（实测会正确跳过封面）。
  - 附带修正：mediainfo 对 MKV 封面同样报 `@type=Video`（原注释称其为 `@type=Image`，与实测不符）。

- **修复 `audio_extract` 预设产出两条重复音轨**（P1）
  - 根因：字幕/流映射的守卫条件写成了"预设非 video **且** 文件非视频"，
    音频类预设作用于视频文件时不早退，会额外插入 `-map 0:a?`，
    与预设自带的 `-map 0:a:0` 叠加成重复音轨（实测产物 2 条一模一样的 AAC）。
  - 修复：守卫改为只按预设类型判断——非视频预设一律不参与流映射。

- **修复"已成功落盘"的任务被改判为"已取消"**（P1）
  - 根因：引擎用 `signal.aborted || result.status === CANCELLED` 且排在成功分支之前；
    用户在文件写完后点"终止"，任务就被记成已取消，成功数少计、UI 显示与实际产物矛盾。
  - 修复：只依据本次尝试的真实结果判断；会话级取消语义仍由 `summary.isCancelled` 单独承担。

- **修复预设字段类型告警"谎报已忽略"**（P1）
  - 根因：类型不匹配的字段（如 YAML 里误写 `dimension: "1080"`）只告警不剔除，
    字符串一路进入尺寸计算并抛错，异常被吞成"跳过"，导致该预设下每个文件都被跳过。
  - 修复：未知字段与类型不匹配字段一律真正剔除，回落到继承/默认值；告警文案改为 `dropped`。

- **修复未知预设名抛原生 TypeError**：改为抛出带可用预设列表的 `PRESET_NOT_FOUND`。

- **修复源码率缺失时算出 `-48000`**：显式夹到非负。

- **修复极小/极端长宽比时目标尺寸退化为 0 而静默不缩放**：最小边钳到 2。

- **修复 `detectHardwareCapabilities({ force: true })` 形同虚设**：force 未透传进实际探测函数。

- `ffprobe` 探测字段补上 `index` 与 `nb_frames`（原字段清单缺前者，导致绝对流序号拿不到）。
