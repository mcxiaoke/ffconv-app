# 变更记录

## 2026-09-30

### 修复（第一批：转码引擎 core/transcode、core/lib）

- **修复封面图被当作主视频流，导致转码产出 1 帧静态图却报"成功"**（P0）
  - 根因：ffmpeg 参数里硬编码 `-map 0:v:0`（"第 0 个 video 流"），而内嵌封面也被探测为 video 流。
    带封面的 MKV 实测封面即 stream0、真实视频为 stream1，于是选中封面；
    ffmpeg 退出码为 0，且产物大小校验也拦不住，UI 显示成功。
    另实测：只给 `-map 0:a?` 而不给视频流时，ffmpeg 会自动补回 stream0（封面）。
  - 修复：媒体信息新增**绝对流序号** `video.streamIndex`（ffprobe `index` / mediainfo `StreamOrder`），
    流映射改用 `-map 0:<绝对序号>`；两种探测器的封面识别统一为"三档"判定
    （确证封面 attached_pic/@type=Image、疑似封面=静帧编码器、正常视频），
    取不到序号时整组 `-map` 都不输出，交由 ffmpeg 默认流选择（实测会正确跳过封面）。
  - 附带修正：mediainfo 对 MKV 封面同样报 `@type=Video`（原注释称其为 `@type=Image`，与实测不符）。

- **修复 `audio_extract` 预设产出两条重复音轨**（P1）
  - 根因：字幕/流映射的守卫条件写成了"预设非 video **且** 文件非视频"，
    音频类预设作用于视频文件时不早退，会额外插入 `-map 0:a?`，
    与预设自带的 `-map 0:a:0` 叠加成重复音轨（实测产物 2 条一模一样的 AAC）。
  - 修复：守卫改为只按预设类型判断——非视频预设一律不参与流映射。

- **修复"已成功落盘"的任务被改判为"已取消"**（P1）
  - 根因：引擎用 `signal.aborted || result.status === CANCELLED` 且排在成功分支之前；
    用户在文件写完后点"终止"，任务就被记成已取消，成功数少计、UI 显示与实际产物矛盾。
  - 修复：只依据本次尝试的真实结果判断；会话级取消语义仍由 `summary.isCancelled` 单独承担。

- **修复预设字段类型告警"谎报已忽略"**（P1）
  - 根因：类型不匹配的字段（如 YAML 里误写 `dimension: "1080"`）只告警不剔除，
    字符串一路进入尺寸计算并抛错，异常被吞成"跳过"，导致该预设下每个文件都被跳过。
  - 修复：未知字段与类型不匹配字段一律真正剔除，回落到继承/默认值；告警文案改为 `dropped`。

- **修复未知预设名抛原生 TypeError**：改为抛出带可用预设列表的 `PRESET_NOT_FOUND`。

- **修复源码率缺失时算出 `-48000`**：显式夹到非负。

- **修复极小/极端长宽比时目标尺寸退化为 0 而静默不缩放**：最小边钳到 2。

- **修复 `detectHardwareCapabilities({ force: true })` 形同虚设**：force 未透传进实际探测函数。

- `ffprobe` 探测字段补上 `index` 与 `nb_frames`（原字段清单缺前者，导致绝对流序号拿不到）。

### 修复（第二批：主进程 src/main、preload、IPC 契约）

- **修复"复制"功能全部失效，且界面谎报"已复制"**（P0）
  - 根因：preload 直接 `import { clipboard } from "electron"`，但主进程开启了 `sandbox: true`，
    沙箱 preload 的 electron 白名单**不含** clipboard（实测为 `undefined`，调用即抛 TypeError）。
    旧实现在 preload 里 try/catch 吞掉异常返回 `false`，而渲染层兜底分支写作
    `if (window.api?.copyText) {...} else { navigator.clipboard... }`，
    `copyText` 永远存在 → 兜底永不执行；`navigator.clipboard` 又因未授权而抛
    `NotAllowedError`。结果：点了没反应，界面却显示"已复制"，剪贴板仍是旧内容。
  - 修复：新增 `system:copy-text` IPC 通道，由主进程写入剪贴板；
    并在渲染层按返回值决定是否提示成功。
  - 顺带修正 `showItemInFolder` 的同步 `statSync`（网络盘会阻塞主进程 20~30s）。

- **修复"转码后删除源文件"的安全门可被渲染层自行绕过**（P0）
  - 根因：主进程校验 `options.deleteSourceConfirmed || options.autoConfirm`，
    而这两个都是渲染层 IPC 载荷里的普通布尔字段，真正的用户确认却在渲染层的
    `window.confirm`。等于这道不可撤销操作的门由信任度最低的一方自己声明通过。
  - 修复：确认改由**主进程**弹原生对话框完成；移除 `autoConfirm` 旁路；
    渲染层只表达意图。用户在原生框点"取消"按**正常取消**处理（不再显示"异常"并弹失败提示）。

- **修复"失败自动切换 CPU 模式重试"是死代码**（P1）
  - 根因：引擎判定顺序为 `shouldRetry → confirmRetry → retryCount++`，
    而主进程只传了前者；`confirmRetry` 缺失时返回 `undefined`，
    `if (!retryConfirmed) break` 必然成立 —— 实测 `runTask` 只被调用 1 次、
    `retryCount` 恒为 0。硬件编码失败因此从不自动回退 CPU。
  - 修复：补上 `confirmRetry`（自动重试是宿主既定策略，无需再次询问用户）。

- **修复并发启动可跑起两个引擎写同一批文件**（P1）
  - 根因：`startExecution` 的守卫与 `status = "RUNNING"` 之间隔着
    `await ensureFfmpegPath()`，两次并发调用会同时穿过守卫、各自占位，
    后者覆盖前者的 AbortController。
  - 修复：状态与 AbortController 提前到任何 await 之前占位；启动阶段失败会把状态还回去。

- **修复并发重建计划会静默丢弃先到的计划**（P1）：`createPlan` 守卫补上 `PLANNING`。

- **修复"终止"可能把状态永久卡在 STOPPING**（P1）
  - 根因：`stopExecution` 只看 `abortController` 是否存在。在
    "onSummary 已落终态、`.finally()` 尚未执行"的 microtask 窗口内它仍非 null，
    此时点"终止"会把状态改写为 STOPPING，而引擎已结束、不会再发任何事件。
  - 修复：`stopExecution` 额外校验 `status === "RUNNING"`；执行收尾的 `.finally()`
    增加兜底，把残留的 RUNNING/STOPPING 落回终态。

- **修复运行中清空输入会破坏会话状态一致性**（P1）
  - `clearStagedInputs`/`removeStagedInputs` 在执行期间直接返回，不再清空 `currentPlan`
  （否则终态判定读到空数组会把"全部成功"标成 STOPPED，且路径白名单丢失计划产物）。

- **修复 `isExecuting()` 把"规划中"当成"正在转码"**：关窗/重载提示曾误报
  "正在写入的文件可能损坏"，而规划阶段一个字节都没写。
  拆分为 `isExecuting()`（真正在写文件）与 `isBusy()`（含规划，供 reload 守卫用），
  并按状态区分提示文案。

- 其他：设置 `app.setAppUserModelId`（Windows 转码完成通知此前可能根本不弹）；
  补 `setPermissionCheckHandler`（同步权限检查此前未被拦截）；
  单实例锁失败后不再继续注册 IPC 与生命周期回调；`second-instance` 在无窗口时补建窗口；
  preload 改用 `MENU_ACTION_CHANNEL` 常量而非硬编码字串；
  `ENV_SET_CUSTOM_PATHS` 的类型断言修正为包含 `mediainfo`。
